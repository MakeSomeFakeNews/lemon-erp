# 柠檬ERP 开发文档

本文档介绍柠檬ERP 的功能细节、架构设计与二次开发约定。项目简介、截图与快速开始见根目录 [README](../README.md)。

| 端 | 技术栈 |
| --- | --- |
| 后端 | Java 17、Spring Boot 4.1、Spring Security + JWT、MyBatis-Plus 3.5、Redis、Flowable 8（工作流） |
| 前端 | Vite、Vue 3、Ant Design Vue 4、Vue Router 4、Pinia、Axios、ECharts 5 |

## 功能

- **供应链管理**：供应商（供货价格、默认供应商）、客户（信用额度、账期）；采购 / 销售订单（审核可接入审批流程）→ 采购入库 / 退货、销售出库 / 退货（自动生成仓库单据、回写订单进度）；物流发运与跟踪；供应商评估与绩效（准时交货率、退货率）；采购合同 / 框架协议（按合同价下单、额度控制）、招标采购（密封投标、开标比价、定标）；供应商门户（订单确认、送货通知、对账、投标、质量索赔）；促销、返利、经销商门户（订货、渠道库存上报）、外部订单导入（见「供应链管理」）
- **生产制造**：工作中心、物料清单与工艺路线（多版本、循环引用校验）；物料计划属性（自制 / 采购 / 委外 / 虚拟件、提前期、批量规则、超领比例、替代料，在物料管理中维护）；主生产计划（可由销售订单生成）→ MRP 运算（多级展开、低层码、净需求）→ 下达工单 / 采购订单；工单下达、齐套分析与缺料下单、领料 / 退料（超领控制）、补料申请、报工、完工入库；设备台账、保养提醒与维修（见「生产制造」）
- **质量管理**：检验方案（定性 / 定量项目、GB/T 2828.1 AQL 抽样）；来料 / 过程 / 成品 / 首件检验，按方案逐项录入自动判定，首件合格前限制报工；不合格品处理（MRB，评审处置可接入审批，联动冻结库存、报废出库、返工工单）；纠正预防（8D）；供应商质量索赔冲减应付；合格率趋势、不良柏拉图、供应商排名、SPC 控制图与 Cp / Cpk（见「质量管理」）
- **财务管理**：会计科目、凭证（审核、记账）、期末结账（自动结转损益）；科目余额表、明细账、资产负债表、利润表；应收应付（由出入库自动生成）、收付款核销、账龄分析；固定资产与折旧、领用调拨履历、资产盘点、低值易耗品；成本核算（月末一次加权平均、工单料工费）、标准成本与成本差异分析；预算编制与执行分析。业务单据一键生成凭证（见「财务管理」）
- **人力资源**：岗位与职级、员工档案（入职 / 转正 / 调岗 / 离职异动记录）；招聘需求（可接入审批）→ 候选人 → 面试 → 录用入职；培训计划与记录；班次、节假日、打卡与补卡、月度考勤汇总；请假 / 加班申请（可接入审批）、假期余额；薪资档案、月度工资表（考勤扣款、加班费、绩效奖金、社保公积金、个税）→ 计提与发放凭证；绩效方案、考核、自评与评分；员工自助（见「人力资源」）
- **客户关系**：客户（我的 / 团队 / 公海，领取、分配、放回）与联系人；线索 → 转化为客户和商机；销售机会（阶段漏斗、赢单生成销售订单）、跟进记录；市场活动（成本、线索、ROI）；服务工单（处理时限、序列号保修判断、满意度）；客户分析（漏斗、RFM、趋势、来源、销售排行）（见「客户关系」）
- **项目管理**：项目、成员与投入比例；计划进度（WBS 任务树、前置任务、进度汇总、甘特图）；资源负荷；工时填报与审批；成本预算、费用录入、项目领料；项目核算（收款计划、开票生成应收、完工百分比确认收入、挣值分析）（见「项目管理」）
- **商务智能**：数据仓库（销售 / 采购 / 库存快照 / 生产 / 财务事实表，定时与手动同步）；多维分析（行列维度透视、筛选、下钻、图表）；自定义报表与仪表盘（可共享）；经营驾驶舱；决策支持（销售预测、ABC 分析、呆滞物料、预警规则）（见「商务智能」）
- **仓库管理**：仓库、库位、物料（批次 / 序列号管理、安全库存）；入库单、出库单、调拨单、盘点单（草稿 → 确认后更新库存）；库存查询（明细 / 按物料汇总、低于安全库存预警、临期提示）、库存流水、批次与序列号追踪；库位区域与上架策略、波次拣货、装箱、条码标签，手机 / PDA 移动作业（扫码收货、上架、拣货、盘点）（见「仓库管理」）
- **系统管理**：用户、部门（树形）、角色、菜单（目录/菜单/按钮三级权限）、字典
  - 部门管理：左侧组织架构树，右侧部门信息与成员，可直接新增成员、添加已有用户、批量调整部门；部门负责人关联用户，即审批流程中的「部门主管」
  - 角色管理：左侧角色列表（含成员数），右侧按「基本信息 / 菜单权限 / 数据权限 / 成员」分页签管理，未保存修改有提示
- **流程中心**：仿钉钉的流程设计器（审批人 / 抄送人 / 条件分支 / 并行分支，依次审批、会签、或签）+ 表单设计，一键发布为 BPMN 流程；发起申请、我的待办 / 已办 / 申请、抄送我的、流程实例管理；同意、拒绝、转交、撤回、终止，审批记录与流程进度图。业务单据可通过 `FlowApi` 接入审批（见「工作流」）
- **SaaS 多租户**（可选，`lemon.tenant.enabled`）：共享数据库按 `tenant_id` 隔离；租户、租户套餐（限定可用菜单）、到期时间与账号数量上限；新租户自动开通管理员并初始化基础数据（见「SaaS 多租户」）
- **数据权限**：角色可配置 全部 / 自定义部门 / 本部门 / 本部门及以下 / 仅本人，多角色取并集；声明式注解，业务模块可直接复用
- **系统监控**：在线用户（强制下线）、操作日志、登录日志（均带 IP 归属地）、服务监控（CPU/内存/JVM/磁盘）、缓存监控（Redis 指标、命令统计、缓存管理）、定时任务（Cron、启停、立即执行、执行日志）
- **首页**：数据概览、业务待办（各模块汇总的待处理事项）、近 7 天登录趋势、最近操作
- **个人中心**：修改资料、上传头像、修改密码
- **平台功能**：站内消息（审批提醒、到期提醒、预警）、Excel 导出 / 导入、单据附件、单据打印、字段变更历史、参数设置（登录验证码、密码策略、会话、水印等）（见「平台功能」）
- **权限**：接口级 `@PreAuthorize`、按钮级 `v-perm`、菜单动态路由；修改角色/菜单后立即生效
- **登录会话**：JWT + 服务端会话，退出登录、强制下线、停用用户、重置密码后 token 立即失效
- **界面**：多标签页、面包屑、暗色主题、全屏、固定页头且只有表格滚动、表格列设置/密度、字典标签、图标选择器

## 快速开始

### 1. 后端

dev 环境默认连接本机 MySQL `localhost:3306/lemon_erp`（root / root）和本机 Redis，可用环境变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 覆盖。

工作流引擎的 `ACT_` 开头的表由 Flowable 在启动时自动创建 / 升级，不在 `init.sql` 中。MySQL 的 `DB_URL` 需要带上 `nullCatalogMeansCurrent=true`（dev 默认已带），否则 Flowable 可能误读其它库的表结构。

```bash
mysql -uroot -p -e "CREATE DATABASE lemon_erp DEFAULT CHARSET utf8mb4"
mysql -uroot -p lemon_erp < sql/init.sql   # 注意：会删除并重建全部表
./gradlew bootRun
```

打包：`./gradlew build` 生成 `lemon-admin/build/libs/lemon-erp.jar`，`java -jar lemon-erp.jar --spring.profiles.active=prod` 运行。

### 多环境配置

| 环境 | 配置文件 | 数据库 | 缓存 |
| --- | --- | --- | --- |
| dev（默认） | `application-dev.yml` | 本机 MySQL | 本机 Redis |
| prod | `application-prod.yml` | 全部取环境变量，无默认值 | Redis |

切换环境：`--spring.profiles.active=prod`。常用环境变量：`DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`JWT_SECRET`（生产必须设置，至少 32 字节）、`LEMON_TENANT_ENABLED`（SaaS 多租户）、`LEMON_DEMO_ENABLED`（演示模式）。

**演示模式**（`lemon.demo.enabled`，环境变量 `LEMON_DEMO_ENABLED`，默认 `false`）：用于搭建对外演示环境。开启后所有用户只能查看，除 GET 以外的请求都会被 `framework/demo/DemoModeInterceptor` 拦截并提示「演示模式下不能新增、修改、删除数据」；登录、退出、标记消息已读，以及用 POST 传参的只读查询（多维分析、促销预览、上架建议、单据打印）在 `lemon.demo.allowed-paths` 白名单中放行。顶部导航和登录页显示「演示模式」提示（`GET /auth/config` 返回 `demoMode`）。定时任务不受影响。新增用 POST 传参的只读查询接口时，要把路径加到白名单。

头像等上传文件保存在 `lemon.upload.path`（默认 `./uploads`），通过 `/api/files/**` 访问。

### 客户端 IP 与归属地

- 后端开启了 `server.forward-headers-strategy: native`：请求来自**内网代理**（10/8、172.16/12、192.168/16、127/8 等）时，才会采用 `X-Forwarded-For` 中的地址作为客户端 IP；外部直接伪造该请求头无效。代理不在内网时，用 `server.tomcat.remoteip.internal-proxies` 配置代理地址（正则）。
- 本地开发时 Vite 代理已开启 `xfwd`。在本机访问看到的是 `127.0.0.1 / 内网IP`，属于正常现象。
- 生产环境 Nginx 示例：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

- 归属地使用 [ip2region](https://github.com/lionsoul2014/ip2region) 离线库（`lemon-framework/src/main/resources/ip2region/ip2region_v4.xdb`），启动时加载到内存，不调用任何外部接口。下载最新的 `ip2region_v4.xdb` 覆盖即可更新数据。目前只内置 IPv4 库，公网 IPv6 显示「未知」。

## 权限模型

`sys_user` ⇄ `sys_user_role` ⇄ `sys_role` ⇄ `sys_role_menu` ⇄ `sys_menu`

`sys_dept`（树形，`leader_user_id` 为负责人）⇠ `sys_user.dept_id`；`sys_role.data_scope` + `sys_role_dept`（自定义数据权限的部门）

`sys_menu.type`：`M` 目录、`C` 菜单（对应前端页面）、`F` 按钮（只有权限标识）。

菜单层级：一级目录是**模块**，和「首页」一起显示在页面顶部的导航栏；侧边栏只显示当前模块的菜单，在首页、个人中心等不属于模块的页面显示模块列表。模块下可以再建一层目录作为侧边栏的**分组**（如 供应链 → 采购 / 销售 / 往来单位），分组不填路由地址，页面地址仍拼接在模块路径之后（`/scm/purchase`）。切换模块时回到该模块上次打开的页面；移动端抽屉显示完整的菜单树。新增页面放在对应的分组下，并给需要的角色勾选（勾选页面会自动勾选所在分组和模块）。

权限分两层：

| 层级 | 控制什么 | 配置位置 |
| --- | --- | --- |
| 功能权限 | 能看到哪些菜单、能调用哪些接口、能点哪些按钮 | 角色管理 →「编辑」→ 菜单权限 |
| 数据权限 | 能看到、能操作哪些部门的数据 | 角色管理 →「数据权限」（按钮权限 `sys:role:dataScope`） |

角色成员的增减使用独立的按钮权限 `sys:role:assignUser`。

内置角色（按岗位预置菜单和按钮权限，可在「角色管理」中调整；所有内置角色都有员工自助、流程中心个人页面、费用报销和借款申请）：

| --- | --- | --- | --- |
| 超级管理员 | admin | 全部 | 全部权限 |

防越权规则（非超级管理员）：不能分配超级管理员角色；不能授予自己没有的菜单权限；不能授予超出自己范围的数据权限；不能修改超级管理员角色；不能重置密码、修改、停用、删除超级管理员账号。角色、菜单、部门变更后权限缓存立即清理。

- **后端接口权限**：`@PreAuthorize("@ss.hasPerm('sys:user:add')")`，见 `framework/security/PermissionService`。
- **操作日志**：在接口上加 `@OperLog(title = "用户管理", type = OperType.INSERT)` 即自动记录（异步写库，密码字段自动脱敏）。
- **前端菜单/路由**：登录后请求 `/auth/menus`，按菜单的 `component` 字段（相对 `lemon-web/src/views`，如 `system/user/index`）动态注册路由，见 `lemon-web/src/router/index.js`。
- **前端按钮权限**：`v-perm="'sys:user:add'"`；用在 `a-popconfirm` 这类没有根元素的组件上时，需要外面再包一层元素。

## SaaS 多租户

开关 `lemon.tenant.enabled`（环境变量 `LEMON_TENANT_ENABLED`，默认 `false`）。关闭时只有平台租户，行为与单租户系统完全一致；开启后：

- **隔离方式**：共享数据库、共享表，业务表都有 `tenant_id` 列（唯一约束为「原列 + tenant_id」，编码、单号在租户内唯一）。使用 MyBatis-Plus 的多租户插件 `TenantLineInnerInterceptor`，所有 SQL（包括 mapper XML 中的 JOIN、子查询、UNION）自动追加 `tenant_id = 当前租户`，INSERT 自动填充，业务代码不需要关心租户。插件只在开启时注册。
- **平台共享的表**（没有 `tenant_id`）：菜单、字典、定时任务、租户与套餐，以及只以全局 ID 关联的用户角色 / 角色菜单 / 角色部门关系表，见 `TenantProperties.ignoreTables`。
- **当前租户**：`framework/tenant/TenantContext`。已登录请求由 `JwtAuthenticationFilter` 按会话设置，登录接口按填写的租户名称设置，`@Async` 线程由 `TenantTaskDecorator` 传递，定时任务由调度器按租户逐个执行（日志汇总各租户结果）。没有租户上下文时访问租户表直接报错，避免漏加条件。需要切换时用 `TenantContext.callAs(tenantId, ...)`。
- **平台租户**（ID 1，`init.sql` 中的「柠檬科技」）：不受套餐限制，管理租户和套餐；菜单、字典、参数设置、租户、服务监控、缓存监控、定时任务是平台专属功能（`PlatformFeatures`），不能加入套餐，其他租户即使被分配也不生效。超级管理员 = 平台租户中的 `admin` 角色。
- **租户套餐**：限定租户可用的菜单。其他租户的 `admin` 角色是租户管理员，菜单与套餐一致、随套餐修改自动同步；其他角色的权限也以套餐为上限。
- **新建租户**：开通根部门、租户管理员账号（首次登录需改密码）、复制平台的内置岗位角色（菜单取与套餐的交集），再由各模块的 `TenantInitializer` 从平台复制基础数据：会计科目和币种、班次、预警规则、流程模型（未发布的草稿，审批角色换成新租户中的角色）。
- **租户生命周期**：停用或到期后无法登录，已登录的会话立即失效；删除只删除租户记录（业务数据保留）；账号数量达到上限后不能再新增用户或录用开通账号。
- **工作流**：流程定义按租户部署（`tenantId`），同一流程标识在各租户独立编号版本；流程实例查询都带租户条件。
- **登录**：开启后登录页显示「租户」输入框（`GET /auth/config` 返回 `tenantEnabled`），用户名只在租户内唯一。

写新代码时注意：
- 新建业务表都要加 `tenant_id BIGINT NOT NULL DEFAULT 1`，唯一约束末尾加 `tenant_id`；平台共享的表登记到 `TenantProperties.ignoreTables`。
- 不要写 `INSERT ... SELECT`：插件对它的处理不完整（SELECT 有 JOIN 时追加的列名有歧义，UNION 不加条件），先查询再批量 `INSERT ... VALUES`（示例 `BiEtlService`）。
- 不要用 `TRUNCATE`，开启 SaaS 时改用带条件的 `DELETE`（示例 `SysOperLogService.clean`）。
- 新增缓存时，按用户名、编码等租户内唯一的值作 key 要带上租户 ID（示例 `PasswordPolicy`）。
- 新租户需要的基础数据，在本模块实现 `TenantInitializer`。

## 数据权限

数据权限是框架能力（`framework/security/datascope`），基于 MyBatis-Plus 的数据权限拦截器实现，业务代码只需要声明「哪张表、哪一列表示所属部门、哪一列表示所属用户」：

```java
// 标注在 Service 的查询方法上，方法内对 biz_order 表的查询自动追加：
//   AND (biz_order.dept_id IN (当前用户可访问的部门) OR biz_order.create_by = 当前用户)
// 列表和分页 count 都会生效
@DataPermission(table = "biz_order", deptColumn = "dept_id", userColumn = "create_by")
public PageResult<BizOrder> page(...) { ... }
```

- 用户的数据权限范围（`DataScope`）在登录用户加载时计算，随权限缓存一起缓存，见 `SysDataScopeResolver`。
- 无法使用注解时（同一个类内部调用、修改前的权限校验）用编程方式：`DataPermissionContext.execute(rule, () -> ...)`，示例见 `SysUserService.checkDataScope`。
- 只建议用在查询上：写操作中的唯一性校验等查询不应受数据权限影响。
- 没有启用规则的 SQL 不会被解析，不影响其它查询的性能。

## 工作流

基于 [Flowable 8](https://www.flowable.com/open-source)（BPMN 2.0）。业务人员在「流程模型」中用仿钉钉的设计器设计表单和流程，发布后由后端转换为标准 BPMN 部署到引擎；用户和组织架构直接使用系统自己的表（不启用 Flowable IDM）。

### 使用

1. 「流程中心 → 流程模型」新建模型，点「设计」：
   - **表单设计**：单行 / 多行文本、数字、日期、下拉选择，字段值保存为同名的流程变量，条件分支中可引用。
   - **流程设计**：审批人（指定成员 / 指定角色 / 部门主管 / 发起人自己；依次审批 / 会签 / 或签；审批人为空时自动通过或转交超级管理员）、抄送人、条件分支（条件组之间「或」、组内「且」，必须有一个默认分支）、并行分支。
   - **部门主管**：从发起人所在部门向上数到第 N 级部门（所在部门为第 1 级），取该部门的负责人；该部门没有负责人或负责人就是发起人时继续向上查找，都没有时按「审批人为空」处理。部门负责人在「部门管理」中设置。
2. 保存并发布：每次发布生成一个新版本，已发起的流程继续按原版本运行。
3. 「发起申请」填写表单提交；审批人在「我的待办」中同意 / 拒绝 / 转交；发起人可在审批中撤回；管理员可在「流程实例」中终止。
4. 任一审批人拒绝，整个流程立即结束（包括其它并行分支），状态为「已拒绝」。

### 架构

```
framework/workflow          业务模块接入工作流的契约（不依赖流程引擎）
├── FlowApi                 发起 / 撤销流程、查询状态
├── FlowStatus              流程状态 RUNNING / APPROVED / REJECTED / CANCELED（字典 wf_status）
├── FlowFinishedEvent       流程结束事件（通过、拒绝、撤回、终止）
├── FlowTaskAssignedEvent   任务分配事件（可用于待办提醒）
└── identity                FlowIdentityProvider：工作流所需的用户、角色查询，由 system 模块实现

modules/workflow            Flowable 集成
├── model                   设计器 JSON 模型（与前端约定）：FlowNode 节点树、FormField 表单字段、条件运算符等
├── engine                  引擎扩展，不含页面业务逻辑
│   ├── bpmn                FlowDesignValidator 设计校验、BpmnModelConverter 节点树 → BPMN
│   ├── meta                FlowMetaService：读取随部署保存的流程设计（按流程定义 ID 缓存）
│   ├── assignee            审批人策略 AssigneeStrategy + 分派器 flowAssignee
│   ├── expression          条件计算 flowCondition
│   └── listener            结束监听（通过 / 拒绝）、抄送、任务分配事件
├── service                 模型发布、发起、待办 / 已办、审批、抄送、实例详情、FlowApi 实现
└── controller / entity / mapper / dto
```

关键设计：

- **BPMN 只描述流转结构**：审批人、分支条件等运行时配置不写进 BPMN，设计 JSON（`flow-design.json`）随 BPMN 放在同一个部署中，由表达式 Bean 按节点 ID 读取。每个流程定义版本都自带对应的设计，详情页按发起时的版本展示表单和进度。
- **审批节点 = 多实例用户任务 + 结果网关**：会签 / 或签 / 依次审批由多实例的完成条件实现；拒绝时设置 `wfRejected` 结束多实例，经网关流向终止结束事件（同时结束并行分支）。
- **条件在 Java 中计算**（`ConditionOperator`），不拼接表达式，避免表达式注入。
- **状态**保存在流程实例的 `businessStatus` 上，列表按状态筛选直接走引擎查询。
- **审批意见**使用 Flowable 的 Comment，处理结果另存为任务局部变量 `wfAction`，已办列表一次查询即可带出。

### 业务单据接入审批

业务模块只依赖 `framework/workflow`，不直接使用 Flowable：

```java
// 1. 声明业务流程及其变量（设计器的条件分支据此提供可选变量，「发起申请」中不显示该流程）
@Bean
public FlowBusiness orderFlow() {
    return FlowBusiness.of("order_approve", "订单审核", Variable.number("amount", "订单金额"));
}
// 然后在「流程模型」中设计并发布标识为 order_approve 的流程

// 2. 提交审批（当前登录用户为发起人）
String instanceId = flowApi.start("order_approve", "order:" + order.getId(), Map.of("amount", order.getAmount()));

// 3. 监听审批结果回写单据状态；@EventListener 与审批操作在同一事务中，抛异常会回滚审批
@EventListener(condition = "#e.processKey == 'order_approve'")
public void onOrderApproved(FlowFinishedEvent e) {
    Long orderId = Long.valueOf(e.businessKey().substring("order:".length()));
    orderService.updateStatus(orderId, e.status());
}
```

只需在提交后处理的副作用（发消息、调用外部系统）用 `@TransactionalEventListener`。

## 仓库管理

代码在 `modules/wms`，前端 `views/wms`、`components/wms`。

### 概念

| 概念 | 说明 |
| --- | --- |
| 库存位置 | 仓库 + 库位 + 物料 + 批次，对应 `wms_stock` 一行。库位可不指定（`location_id = 0`），未启用批次管理的物料批次号为空串 |
| 批次管理 | 物料启用后，出入库必须填写批次号；首次入库时登记批次及生产日期、有效期（`wms_batch`） |
| 序列号管理 | 物料启用后，数量必须为整数，出入库逐个登记序列号；`wms_serial` 记录每个序列号当前位置和是否在库，`wms_serial_log` 记录完整轨迹 |
| 单据 | 入库、出库、调拨共用 `wms_stock_doc`（`kind` 区分），盘点为 `wms_check`。草稿可以修改、删除，**确认后才更新库存**，不能再修改 |
| 库存流水 | 每次库存变动一条（`wms_stock_flow`），数量带正负号 |

物料发生过库存业务后不能再修改批次 / 序列号管理方式；仓库、库位、物料被使用后不能删除，只能停用。

### 库存变动

所有库存变动都经过 `StockService.apply`，在单据确认的事务中执行，任一行失败整张单据回滚：

- 扣减用条件更新 `UPDATE ... SET qty = qty - ? WHERE ... AND qty >= ?`，并发确认也不会出现负库存；
- 出库、调出的序列号必须在该库存位置在库；已在库的序列号不能重复入库，已出库的可以重新入库（退货）；
- 确认时先把单据状态从草稿条件更新为已完成，防止重复确认；
- 盘点以**确认时**的库存为账面数量，库存调整为实盘数量。序列号物料按实盘序列号盘点：「按库存生成」时带出在库序列号，多出的盘盈入库、缺少的盘亏出库。
  盘点单可勾选「冻结仓库」：盘点完成前该仓库不能出入库、调拨。发布了 `wms_check` 流程时，有差异的盘点确认后先审批，通过后才调整库存；
- 库存预留（`wms_reservation`）不锁定库位批次，只保证「仓库可用库存 ≥ 全部剩余预留」：出库、调拨扣减库存后校验扣减的物料仍满足预留（盘亏除外），销售出库先核销本订单的预留；
- 销售、生产、项目、委外、服务领用出库不能发出已过期的批次，过期的可「报废出库」（`SCRAP`，手工出库可选）或调拨到不良品仓。

单据号为「前缀 + 日期 + 4 位流水」（入库 RK、出库 CK、调拨 DB、盘点 PD），流水号存在 `wms_doc_sequence`，与单据在同一事务中生成。

### 冲销、在途与主数据扩展

| 功能 | 说明 |
| --- | --- |
| 冲销 | 已完成的手工出入库单、调拨单可「冲销」：生成红字单据（数量为负，`red_of` 指向原单），库存按原单反向变动（入库冲销要求库存仍在原库位）。业务单据（采购入库、销售出库、工单领料等）生成的须在业务单据中退货；成本核算按单据种类归集，红字单冲减原单 |
| 组装拆卸 | 「库存作业 → 组装拆卸」（`WmsAssemblyService`）：组装消耗子件得到成套件，拆卸把成套件拆为子件；子件可按成套件的默认 BOM 带出（用量 × 数量）。草稿可修改删除，确认后在同一事务中生成并确认出库单、入库单（出入库类型 `ASSEMBLY`，来源单号为组装拆卸单号），之后不能修改，撤回时做一张反向的单据。成本核算（`FinCostService`）：组装的成套件、拆卸的子件按生产入库计入，组装的成套件成本 = Σ 子件数量 × 子件单价，拆卸时成套件成本（数量 × 单价）按子件数量 × 上期单价（或参考成本价，都没有时按数量）分摊；依赖顺序上组装的成套件在子件之后、拆卸的子件在成套件之后计算；出库数量计入其他出库但在凭证中拆出：借 入库物料的存货科目 / 贷 出库物料的存货科目（尾差计入待处理财产损溢），不进入盘盈盘亏。移动加权平均、先进先出的物料按单据逐笔取组装拆卸的入库成本。权限 `wms:assembly:list/add/confirm` |
| 在途调拨 | 调拨单勾选「在途」：确认时只调出（状态 TRANSIT），调入仓库「收货」后才入库 |
| 辅助单位与条码 | 物料可设条码和辅助单位（`wms_material_unit`，1 辅助单位 = 换算率 × 基本单位，可带包装条码）。库存、成本都按基本单位；采购 / 销售订单可按辅助单位录入（保存换算后的基本单位数量、单价及录入单位）；物料选择框可扫码（`/wms/material/barcode`） |
| 多规格物料（SKU） | 「规格属性」维护颜色、尺码等属性及属性值（`wms_attribute`、`wms_attribute_value`，属性值列名为 `attr_value`）。在物料上点「多规格」选择属性和属性值，按组合批量生成 SKU（`WmsVariantService.generate`）：每个 SKU 是独立的物料（编码 = 款式编码-属性值编码，规格 = 属性值，继承单位、分类、批次 / 序列号管理、计价方法等），`template_id` 指向款式，`wms_variant_value` 记录 SKU 的属性值；之后可补充属性值只生成新组合，属性不能中途增减。生成后原物料成为款式（`is_template = 1`）：不在物料选择中，`StockService.apply` 拒绝款式的库存变动；已发生库存业务的物料不能设为款式，款式下有 SKU 时不能删除，被 SKU 使用的属性值不能删除。多规格抽屉中两个属性时按矩阵显示各 SKU 的库存；采购 / 销售订单可「按规格录入」，在款式的规格矩阵中填写数量后逐行加入明细。新租户复制平台的规格属性（`WmsTenantInitializer`） |
| 默认仓库、参考成本、计价方法 | 物料可设默认仓库 / 库位（录入单据时带出）、参考成本价（成本核算没有单价时按此计价，毛利分析未核算的期间也取此价）和存货计价方法（见财务管理「存货计价方法」） |
| 库位区域与类型、上架推荐 | 库位可设区域和类型（存储位、拣货位、收货暂存、发货暂存、不良品位），拣货路径按 区域 → 排序 → 编码；不良品位的库存不参与拣货建议。入库单、调拨单（调入库位）、采购入库、销售退货可「推荐库位」：为没有选库位的行按 物料默认库位 → 已有同批次库存的库位 → 已有该物料库存的库位 → 没有库存的空存储位 / 拣货位（同一次推荐中一个空库位只给一种物料）推荐（`POST /wms/location/putaway`） |
| 仓库类型 | 普通 / 原料 / 成品 / 不良品；不良品仓的库存不计入 MRP、齐套分析、可承诺量、补货建议的可用库存，报废入库只能入不良品仓 |

## 业务联动

业务模块单向依赖：`wms ← scm ← mes ← fin ← hr / crm / pm / bi`，下游调用上游的服务、监听上游的事件，上游不感知下游（例如财务删除凭证时发布 `VoucherDeletedEvent`，工资表监听后解除关联）：

```
采购订单 ─审核─▶ 采购入库 / 退货 ──▶ 仓库入库 / 出库单（已确认，更新库存、批次、序列号）
                       │ TradeDocConfirmedEvent
                       ▼
                    应付单 ─▶ 付款核销 ─▶ 凭证
销售订单 ─审核─▶ 销售出库 / 退货 ──▶ 仓库出库 / 入库单 ──▶ 物流发运
                       │                      └─▶ 应收单 ─▶ 收款核销 ─▶ 凭证
                       ▼
                 生产计划 ─▶ MRP ─▶ 生产工单（领料 / 退料 / 补料 / 完工入库 ─▶ 仓库单据）
                                  └▶ 采购订单（按默认供应商合并）
                 齐套分析（库存按工单优先级分配）─缺料下单─▶ 采购订单（来源 KIT）/ 草稿工单
仓库流水 + 采购金额 + 工单料工费 ─▶ 成本核算 ─▶ 成本结转凭证

采购入库（需来料检验的物料）─▶ 冻结待检 ─来料检验─▶ 合格放行 / 不合格冻结 ─▶ 采购退货优先退冻结库存
发运单（指定承运商供应商、运费）─发货─▶ 运费应付单（销售费用）
设备维修保养费、培训费 ─▶ 费用凭证（制造费用 / 管理费用-培训费）

考勤 + 请假 + 绩效 + 报工计件 ─▶ 工资表 ─▶ 计提凭证 / 发放凭证（fin）
线索 ─▶ 客户（scm_customer）+ 商机 ─赢单─▶ 销售订单（scm，来源 CRM）
服务工单 ─▶ 按序列号查销售出库（wms 序列号轨迹）判断保修；领用备件 ─▶ 服务领用出库单（成本核算计入销售费用）；服务收费 ─▶ 应收单（其他业务收入）
销售订单 / 赢单商机 ─一键─▶ 项目
项目工时 ×（薪资档案折算的小时成本）+ 项目领料（wms 出库单）+ 费用 ─▶ 项目成本；项目开票 ─▶ 应收单（合同负债）
项目月结 ─▶ 人工、费用入合同履约成本；按完工进度 合同负债 ─▶ 主营业务收入，合同履约成本 ─▶ 主营业务成本
全部业务表 ─ETL─▶ 数据仓库（bi_fact_*）─▶ 多维分析 / 报表 / 仪表盘 / 驾驶舱
```

- 销售订单反审核前检查下游：已生成生产计划时不能反审核；关闭订单时未完成的生产计划一并关闭（`OrderStatusChangedEvent`）。订单详情的「单据追溯」页签列出出入库、应收应付、收付款与凭证、发运、来料检验、生产计划、项目（`/bi/trace/order/{kind}/{id}`，各部分按权限返回）。
- 由业务单据生成的仓库单据保存即确认，`wms_stock_doc.source_no` 记录来源单号，库存不足、序列号不在库等错误会让整张业务单据回滚。
- 仓库的手工出入库只能选「其他入库 / 其他出库」；采购、销售、生产、项目、委外等类型只由对应的业务单据生成，否则会绕过应收应付和成本归集（`WmsConstants.MANUAL_TYPES`）。
- 采购入库 / 退货、销售出库 / 退货、工单领料 / 退料 / 完工入库都是**保存即确认**，不能修改删除，错误通过退货、退料冲回。
- 财务报表类查询（成本核算读取仓库流水、采购金额、工单数据）直接在 `fin` 的 XML 中关联上游表，不在上游模块增加只为财务服务的接口。
- 单据号统一由 `DocNoService.next(前缀)` 生成：采购订单 CG、销售订单 XS、采购入库 CR、采购退货 CT、销售出库 XC、销售退货 XT、发运 FY、生产计划 JH、MRP 运算 MR、工单 SC、领料 LL、退料 TL、完工 WG、补料 BL、补料申请 BS、采购合同 CGHT、招标 ZB、送货通知 SH、供应商对账单 DZ、检验 ZJ、工程变更 ECN、技术文档 TD、销售返利 FL、资产盘点 ZCPD、低值易耗品领用 YH、不合格品处理 NC、纠正预防 CP、质量索赔 SZ、维护 WX、应收 YS、应付 YF、收款 SK、付款 FK、招聘 ZP、请假 QJ、工资表 GZ、线索 XL、商机 SJ、服务工单 FW。

## 供应链管理

代码在 `modules/scm`，前端 `views/scm`、`components/scm`。

| 功能 | 说明 |
| --- | --- |
| 供应商 / 客户 | 供应商维护供货价格（含税单价、税率、提前期、最小起订量、有效期、阶梯价：按采购数量取达到的最高一档；过期的价格不再带出、MRP 和请购不使用；可查看采购价格历史），每个物料可设一个默认供应商，采购下单自动带出单价，MRP 按默认供应商生成采购订单；客户有信用额度：审核销售订单时校验 应收余额 + 未完成订单 + 本单 不超过额度，销售出库前再校验一次（超出时暂停出库），客户详情显示信用占用（`/scm/customer/{id}/credit`，应收余额由财务通过 `framework/finance/PartnerBalanceProvider` 提供）；账期决定应收应付的到期日 |
| 采购 / 销售订单 | 共用 `scm_order`（`kind` 区分）。草稿 → 审核 → 部分完成 → 已完成，可反审核（未入库 / 出库时）、关闭。价税合计 = 数量 × 含税单价，税额 = 价税合计 × 税率 / (100 + 税率) |
| 审批 | 在流程中心发布流程标识为 `scm_purchase_order` / `scm_sales_order` 的流程后，「审核」改为发起审批（订单变为审批中），审批通过自动变为已审核，拒绝或撤回回到草稿；没有发布时直接审核。条件分支可使用变量 `amount`（价税合计） |
| 入库 / 出库 / 退货 | 共用 `scm_trade_doc`，按订单明细录入，可拆成多个库位、批次。回写订单明细的已完成 / 已退货数量用条件更新，不会超收超发；单价取订单。退货分两种：**退款**（默认）不影响订单状态、不再补发；勾选**补发 / 补收**时计入 `replenish_qty`，订单恢复相应的未完成数量（未完成 = 订购 - 已出入库 + 待补发） |
| 物流发运 | 由销售出库单生成（按出库单的数据权限读取，一张出库单只能创建一张发运单），待发运 → 运输中（必须有运单号）→ 已签收，运输中可标记异常；每次操作记录物流动态。只有发运权限的用户只能查看销售出库单 |
| 供应商评估 | 质量 40% + 交期 30% + 价格 20% + 服务 10%，≥90 A、≥75 B、≥60 C，否则 D，并更新供应商等级（删除评估后按剩余最近一次评估重新确定）；绩效页按业务数据统计订单数、入库金额、准时交货率（入库日期不晚于交货日期）、退货率 |
| 请购 | 部门提出请购（物料、数量、需求日期、建议供应商），提交后审批（`scm_requisition`），批准后按建议供应商（为空取默认供应商）合并生成草稿采购订单（来源 REQUISITION，单价取阶梯价）；草稿订单删除后请购恢复为已批准 |
| 询价比价 | 一张询价单向多个供应商询价，按供应商录入报价，比价矩阵逐行定标；完成时可用中标价更新供货价格（没有时新建，物料没有默认供应商时设为默认）、按中标供应商生成采购订单（来源 INQUIRY） |
| 销售价目表、报价 | 价目表按物料 × 客户（客户专属价）或客户等级（都为空适用全部）× 起订数量 × 有效期定价，销售订单、报价单、经销商订货、外部订单导入、寄售结算按此取价（客户专属价优先，其次客户等级，再取满足数量的最高一档）。报价单记录价目价和折扣，提交审批（`scm_quotation`），批准且未过有效期时转销售订单（来源 QUOTATION），未成交可标记失效 |
| 促销 | 按期间（订单日期）、客户等级（为空全部）、物料或分类（都为空全部）设置：折扣（成交价 = 原价 × 折扣率，可设起订数量）、满减（适用物料折扣后金额达到门槛减免，按行金额分摊到单价）、买赠（每买 N 个赠 M 个赠品，生成单价为 0 的赠品行）。手工新建 / 修改销售订单时自动应用：每行取最低折扣 → 取减免最多的一个满减 → 买赠；明细记录原价和促销，订单记录促销优惠合计，促销记录应用的订单、优惠金额和赠品数量（修改订单时重算）。录入时按原价，表单实时预览促销价和赠品。已应用的促销不能删除，可停用。权限 `scm:promotion:list/edit` |
| 销售返利 | 客户 × 期间的阶梯返利协议：期间销售额（销售出库 - 退货，含税）达到的最高一档返利率 × 全部销售额。期间结束后结算：红字应收方式由财务生成红字应收单（来源「销售返利」，凭证 借 主营业务收入、销项税额 / 贷 应收账款）；下次订单抵扣方式计入客户返利余额，新建 / 修改销售订单时填写返利抵扣（不超过余额，按行金额分摊到单价）。撤销结算须红字应收单未核销、未生成凭证，或返利余额未被使用。权限 `scm:rebate:list/add/settle` |
| 库存预留、可承诺量 | 已审核的销售订单可按行预留或「一键预留」仓库的空闲库存（可用 − 已预留），出库时核销，订单完成 / 关闭 / 反审核时释放。可承诺量（ATP）：从空闲库存出发，按日期累加采购在途、在制工单产出，扣减未预留的销售待发、工单待领料；现在可承诺的数量是未来累计余额的最小值，并给出指定数量的最早可承诺日期 |
| 发货通知、拣货 | 销售订单生成发货通知（数量不超过未出库且未通知的数量），按先到期先出生成拣货建议（不含过期批次），仓库确认实际拣货（库位、批次、序列号，合计须等于通知数量）后一键生成销售出库单，可打印拣货单 |
| 波次拣货 | 在发货通知中勾选同一仓库的待拣货通知生成波次（也可后续加入、移出），按当前库存重新生成各通知的拣货建议。拣货单把各通知的建议按 库位（区域 → 排序 → 编码）→ 物料 → 批次 汇总，每行列出各通知的分拣数量，可打印；库存不足的明细单独提示。完成拣货时按建议确认各通知的拣货，库存不足或有序列号物料的通知跳过（仍为待拣货，可加入新波次或在发货通知中单独拣货）。权限 `scm:wave:list/add/pick` |
| 装箱打包 | 已拣货（或已出库）的发货通知按箱录入箱内物料、毛重、体积，箱号 = 发货通知号-两位序号，每个明细的装箱合计不超过通知数量；可打印装箱单（打印模板 `scm.packingList`）和箱标签。权限 `scm:delivery:pack` |
| 条码标签 | 物料标签（条码为物料条码，没有时为编码）、库位标签（库位编码）、箱标签（箱号），在物料管理、库位管理中勾选后打印，箱标签在发货通知的装箱中打印。标签纸尺寸、条形码（Code 128）/ 二维码、显示的字段和顺序在「打印模板 - 标签」中设置（模板标识 `label.*`，前端用 jsbarcode、qrcode 生成，每张标签一页） |
| 移动作业 | 顶部导航「移动作业」（`/m`），手机 / PDA 使用的独立布局（没有侧边栏和标签页），扫码枪按键盘输入加回车，扫描内容依次按库位编码、物料条码 / 包装条码（按换算比例计数）/ 物料编码识别，其余作为序列号。扫码收货：选择采购订单，扫描累计数量，未指定库位的按上架策略推荐，生成采购入库单；上架：扫描来源库位（如收货区）列出库存，扫描物料后扫描目标库位或一键推荐，生成同仓库调拨单并确认（没有调拨确认权限时为草稿）；拣货：按发货通知的拣货建议以库位顺序拣货，全部拣完后确认拣货；盘点：选择草稿盘点单，按库位扫码录入实盘数量，账面没有的物料作为盘盈行。页面权限沿用业务权限（`scm:purchaseIn:add`、`wms:transfer:add`、`scm:delivery:pick`、`wms:check:edit`） |
| 欠交清单、补货建议 | 欠交清单列出未完成的销售 / 采购订单明细、逾期天数、已预留和可用库存。补货建议按再订货点：预计库存 = 可用 + 采购在途 + 在制产出 − 销售待发 − 工单待领料，不高于再订货点时建议补货 max(再订货量, 再订货点 + 安全库存 − 预计库存)，按默认供应商的最小起订量取整，可一键生成请购单；定时任务「补货提醒」每天提醒采购人员 |
| 订单变更 | 已审核、部分完成的订单通过变更单修改数量（不少于已完成）、单价、交期，删除未出入库的明细、新增明细；审批（`scm_order_change`）通过后生效，订单版本加 1，变更记录保留新旧值。销售订单数量减少的明细释放库存预留 |
| 多币种 | 订单可选币种，汇率默认取「币种汇率」中订单日期所在月的汇率（可修改）。订单单价、金额为原币；出入库单和应收应付单按订单汇率折算为本位币（成本、凭证、报表都按本位币），同时保留原币金额。外币应收应付按原币收付款：往来按单据记账汇率冲销，与实收实付本位币的差额计入财务费用（汇兑损益）。期末调汇：未核销的原币按期末汇率重估，差额计入财务费用，下月 1 日自动冲回 |
| 采购合同 | 框架协议（约定价格与期限，可设物料数量上限、合同金额上限）或固定数量合同（每个物料有数量上限）；草稿 → 提交（发布 `scm_contract` 后审批）→ 生效 → 关闭。采购订单选择供应商后可引用其在订单日期有效的生效合同：明细按合同价（单价、税率锁定），物料须在合同中、只能本位币；保存和审核时校验数量上限、金额上限（已下单 = 非草稿的引用订单，关闭的订单按已入库数量）。合同详情显示各物料的已下单、已入库和引用的订单；约定了付款天数时，引用合同的订单入库生成的应付单按合同计算到期日 |
| 招标采购 | 招标（物料、数量、投标截止时间、邀请的供应商）发布后通知供应商的门户账号；供应商在门户投标（截止前可修改），没有门户账号的由采购代录线下标书。**开标前看不到报价**（列表只显示已投标的供应商，按提交顺序）；截止后或邀请的供应商都已投标时可以开标，比价矩阵标出各物料最低价和最低总价。定标选择中标供应商，按其报价生成采购合同（固定数量合同，草稿）或采购订单（草稿，来源 TENDER），也可只定标；中标供应商收到通知，门户只显示本供应商是否中标 |
| 供应商门户 | 在「供应商 - 门户账号」中开通账号（关联供应商的用户，只分配「供应商」角色），供应商用该账号登录（SaaS 模式下租户名称与本公司相同），顶部导航只有「供应商门户」：**我的订单**（已审核的采购订单，接受时填写承诺交期、拒绝时填写原因，结果通知制单人；订单详情显示确认结果）、**送货通知**（按订单发起，不超过未收货且未通知的数量；仓库在「采购 - 送货通知」中按实收数量收货，生成采购入库单）、**对账单**（确认或提出异议，填写发票、上传扫描件）、**招标投标**、**质量索赔**（已确认的索赔）。订单审核通过、招标邀请、中标、对账单发送、质量索赔确认时给供应商账号发站内消息。**隔离**：门户接口一律取当前账号关联的供应商（`SecurityUtils.requireSupplierId()`），不接受前端传入；供应商账号即使被分配了其他角色也只保留 `portal:*` 权限，且只能访问门户、登录信息、个人中心、站内消息、字典、附件接口（`PortalKind` / `PortalFeatures`，在 `JwtAuthenticationFilter` 中拦截）；内部用户不显示门户菜单，调用门户接口会被拒绝 |
| 价格控制、历史成交价 | 「价目表 → 价格控制」按物料设置最低销售价、最高采购价（含税、基本单位、本位币）和控制方式（`scm_price_control`，提示 / 禁止保存）。手工录入的销售 / 采购订单保存时（`ScmPriceControlService.check`），单价折算本位币后（促销按原价、赠品不校验）低于最低销售价 / 高于最高采购价且为「禁止保存」时不能保存；「提示」时订单页面在单价下方提示。订单录入时带出该往来单位此物料最近一次成交价（已审核订单，`GET /scm/price-list/history`），没有价目价 / 供货价时默认使用，可点击使用 |
| 经销商门户 | 客户的销售渠道为「经销商」时可填写授权区域、负责销售，并在「客户 - 门户账号」中开通账号（关联客户的用户，只分配「经销商」角色）。经销商登录后只有「经销商门户」：**我要订货**（可订货清单为价目表中当天有效、适用其客户等级的物料，按起订数量阶梯取价；提交后生成来源为「经销商订货」的销售订单草稿，自动应用促销、可抵扣返利余额，记到负责销售名下并通知有审核权限的人员；审核前可撤销），**库存销量上报**（按月上报各产品的当月销量和月末库存，同一月份重复上报覆盖）。内部在「销售 - 渠道库存」查看各经销商的上报和库存可售月数。隔离方式与供应商门户相同（`SecurityUtils.requireCustomerId()`、`dealer:*` 权限、只能访问 `/dealer/*` 和公共接口） |
| 外部订单导入 | 「销售订单 - 导入外部订单」：电商 / 门店订单按统一格式（外部单号、客户编码、下单日期、交货日期、物料编码、数量、含税单价、备注）用 Excel 导入，或由外部系统调用 `POST /scm/sales/import`。同一外部单号的多行生成一张销售订单草稿（来源「外部导入」，记录外部单号，订单号查询也匹配外部单号），单价为空时按价目表取价；外部单号已导入过的整单跳过（防重，`uk_order_external` 唯一约束兜底），其他错误整批不导入 |
| 寄售 | 仓库类型「客户寄售仓」（关联客户）、「供应商寄售仓」（关联供应商），都不计入可用库存。客户寄售：货物调拨到客户寄售仓后仍是本公司存货，客户售出后「寄售结算」生成已审核的销售订单（来源 CONSIGN）并从寄售仓出库，形成应收和销售成本。供应商寄售（VMI）：供应商的货物「寄售入库」到供应商寄售仓，不计入存货成本；领用后结算生成采购订单、采购入库到自有仓库（形成应付），寄售仓做寄售消耗出库 |

权限：订单 `scm:{purchase,sales}:list`、`:add`、`:edit`、`:remove`、`:approve`（审核 / 撤回 / 反审核）、`:close`；入库出库 `scm:{purchaseIn,purchaseReturn,salesOut,salesReturn}:list`、`:add`；发运 `scm:shipment:list`、`:add`、`:edit`、`:remove`、`:track`（发货、动态、异常、签收）；`scm:{supplier,customer}:list/add/edit/remove`（供货价格随供应商的 edit 权限）、`scm:eval:list/add/remove`；请购 `scm:requisition:list/add/edit/remove/order`、询价 `scm:inquiry:list/add/edit/remove`、报价 `scm:quotation:list/add/edit/remove/order`、价目表 `scm:price:list/edit`、促销 `scm:promotion:list/edit`、返利 `scm:rebate:list/add/settle`、预留 `scm:sales:reserve`、发货通知 `scm:delivery:list/add/pick`（出库还需 `scm:salesOut:add`）、欠交清单 `scm:backorder:list`、补货建议 `scm:reorder:list`、订单变更 `scm:{purchase,sales}:change`、寄售结算 `scm:consign:list/settle`、采购合同 `scm:contract:list/add/edit/remove/approve`（提交）`/close`、招标 `scm:tender:list/add/edit`（含发布、取消、代录标书）`/remove/award`（开标、定标）、送货通知 `scm:asn:list/receive`、门户账号 `scm:supplier:portal`、`scm:customer:portal`、渠道库存 `scm:channel:list`；经销商门户 `dealer:order:list/add`、`dealer:report:list/edit`；供应商门户 `portal:order:list/confirm`、`portal:asn:list/add`、`portal:statement:list/confirm`、`portal:tender:list/bid`、`portal:claim:list`。采购合同、招标按创建人部门 + 创建人做数据权限。订单、出入库单、发运单、请购、询价、报价、发货通知按制单人部门 + 制单人做数据权限。

## 生产制造

代码在 `modules/mes`，前端 `views/mes`、`components/mes`。

| 功能 | 说明 |
| --- | --- |
| 工作中心 | 人工费率、制造费用率（元 / 工时），成本核算按报工工时计算直接人工和制造费用 |
| 物料清单（BOM） | 产品可有多个版本，其中一个为默认（MRP 和新建工单使用）；子件用量 + 损耗率 + 位号（如 R1,R2，连续的写成区间 C1-C8，同一 BOM 内展开后不能重复；位号数与整数用量不一致时只提示，按盘、按 kg 计量的物料不受影响），工艺路线为工序、工作中心、标准工时。保存时校验循环引用（子件的下层不能用到产品本身） |
| 物料计划属性 | 物料主数据只有一份，在「仓库管理 - 物料管理」中维护；生产模块另存计划属性（`mes_material_plan`）和替代料（`mes_material_substitute`），在物料编辑抽屉的「生产计划」分区维护（权限 `mes:material:edit`，只有该权限时基础信息只读），列表显示物料属性和计划参数，详情可看被哪些 BOM 使用、在各未结束工单中的需求与分配。**物料属性**：自制（MRP 建议工单）、采购（建议采购订单，有 BOM 也不展开）、委外（向默认供应商即加工商下采购订单，同时展开需要提供的子件）、虚拟件（不入库的中间组件：MRP 不扣库存、不建议生产，需求直接传给子件；工单用料展开为它的子件），不设置时有启用的默认 BOM 为自制、否则为采购。**提前期**优先于 BOM / 供货价格的提前期；**最小批量、批量倍数**用于 MRP 和缺料下单的建议数量；**允许超领比例**是领料上限；**替代料**按比例（替代 1 个主料需要的数量）和优先级设置 |
| 生产计划 | 产品、数量、需求日期，可由销售订单的自制、委外件按「未出库数量 - 已生成计划的数量」生成（重复生成不会重复计划）；确认后参与 MRP，也可以直接「转工单」（工单关联计划）；计划下工单的完工数量达到计划数量时计划自动关闭 |
| MRP | 按默认 BOM 多级展开，计算低层码后逐层计算：净需求 = 毛需求 - (库存 + 在途 - 已分配 - 安全库存)。在途：采购件为未完成的采购订单，自制件为未完工的工单；已分配：未结束工单未领用的用料。物料属性决定是否展开和下达方式（见「物料计划属性」）。建议数量：不低于最小批量和默认供应商的最小起订量，再向上取整到批量倍数，序列号物料取整；建议日期 = 需求日期 - 提前期（物料设置的提前期，否则 BOM 生产提前期 / 供货价格采购提前期），下层需求日期为上层开工日期。下达：自制件生成草稿工单（只有一个计划参与运算时工单关联该计划），采购、委外件按供应商合并为草稿采购订单。再次运算后，之前未下达的建议作废（EXPIRED），避免按过时的数据重复下单 |
| 生产工单 | 保存时按 BOM 生成用料（需求 = 数量 × 用量 × (1 + 损耗率)，虚拟件展开为子件、同一物料合并）和工序。草稿 → 下达 → 生产中（首次领料 / 报工）→ 已完工（完工入库满数量），未完工的可以关闭。领料、退料只能是工单用料，**累计领料不超过 需求 × (1 + 允许超领比例) + 已补料**，退料不超过已领；报工按工序累计合格 + 报废不超过工单数量，且不超过上道工序的累计合格数；完工入库累计不超过工单数量 |
| 齐套分析 | 未结束工单（草稿、已下达、生产中）的每个用料：待领 = 需求 + 已补料 - 已领。全部仓库的库存按优先级依次分配给各工单（已下达 / 生产中在前、草稿在后，再按计划开工日期、工单号），分不到的为缺料。工单齐套状态：已领齐、齐套（没有缺料）、部分缺料（按已领 + 分到的库存还能继续生产）、缺料；可生产数量 = 各用料（已领 - 已补料 + 分配）/ 单位用量的最小值。**生产用料汇总**按物料汇总需求、已领、待领、库存、缺料、在途（采购订单 / 未完工工单），建议下单 = 缺料 - 在途，按批量规则取整；**缺料下单**把采购、委外件按默认供应商合并为草稿采购订单（来源「生产缺料」），自制件生成草稿工单。**替代料切换**：把主料未领的部分换成替代料（主料需求减少，替代料需求 = 数量 × 比例）；草稿工单修改后会按 BOM 重新生成用料，需要重新切换 |
| 补料申请 | 超出领料上限的部分（报废、损耗超标、来料不良等）提交补料申请，物料须为工单用料。流程中心发布了流程标识 `mes_supplement` 的流程时走审批（变量 `woNo`、`reason`、`totalQty`、`suppNo`），否则提交即为待发料；待发料的申请由仓库选择库位 / 批次 / 序列号发料，各物料不超过申请数量，生成「补料」工单单据（BL）和生产领料出库单，计入工单的已领和已补料，成本核算按领料处理；可以分次发料，全部发完后变为已发料，待发料的数量计入齐套分析的待领。审批中、待发料的申请可由申请人撤销，工单关闭时自动撤销；有发料权限的仓库人员发料、查看明细不受申请人部门的数据权限限制 |
| 工程变更（ECN） | 选择产品的基准 BOM 新建变更，复制为新版本（停用，BOM 列表标「变更中」），在物料清单中修改新版本的子件和工序（只在变更草稿时可改，不能启用、设为默认），变更详情按物料、工序号对比新旧版本（新增 / 删除 / 修改）。提交时须有变化；发布 `mes_ecn` 后审批（内置：部门主管 → 质量工程师 → 抄送生产计划员）。批准后到生效日期（今天及以前立即，之后由「工程变更生效」定时任务）生效：新版本启用并接替默认，原版本停用；勾选同步时，使用原版本的草稿工单改用新版本并重新生成用料和工序（已下达的不变）。待生效的可以立即生效或取消（新版本删除）。有变更记录的 BOM 不能删除 |
| 技术文档 | 图纸、规格书、作业指导书、工艺文件、检验标准，可关联物料和工程变更；草稿上传文件（附件）后发布，已发布的最新版本可以升版（复制为新的草稿版本，重新上传文件），新版本发布时上一版本作废；列表只显示各文档的最新版本，详情有版本记录；BOM 详情列出产品和子件的已发布文档 |
| 质量检验 | 见「质量管理」；工艺路线的工序可勾选「首件检验」，工单该工序首件检验合格前累计只能报工 1 件 |
| 完工控制 | 使用了报工的工单，完工入库累计不超过末道工序的累计合格数；物料计划属性勾选「完工需成品检验」时，不超过已确认的成品检验合格数 |
| 计件工资 | 工艺路线可设计件单价（工单下达时带入），报工可指定操作员，计件工资 = 合格数 × 计件单价，计入操作员当月工资表；工作中心的人工费率可参考生产岗位员工的平均小时人工成本 |
| 需求来源 | MRP 除勾选的生产计划外，可计入销售订单中还没有生成生产计划的未出库数量、未来几个月的销售预测（预测扣减同月已有的销售订单）；预测在「MRP 运算」页面维护 |
| 设备维护 | 设备台账按保养周期计算下次保养日期，可筛选到期 / 逾期设备；维修单开始处理时设备变为维修中，完成后恢复维修前的状态（闲置的仍为闲置）并记录停机时长；保养完成后更新保养日期。维护单开始到完成的时间自动记为设备停机（维修为故障，保养为计划保养） |
| 设备 OEE | OEE = 可用率 × 性能率 × 良品率。计划时间按设备所属工作中心的工作日历（每台设备一个资源，没有工作中心的按全厂日历），扣除计划停机（计划保养、无生产计划）；可用率 = 运行时间 / 计划时间（运行时间扣除故障、换型、待料等非计划停机）；性能率 = Σ 报工（合格 + 报废）× 工序标准工时 / 运行时间；良品率 = 合格 / (合格 + 报废)。报工可选择生产设备；停机记录手工登记（同一设备不能重叠）或由维护单自动记录，按天切分且不超过当天日历工时。设备明细有每日趋势和按原因的停机时长。权限 `mes:oee:list`、`mes:equipment:stop`（登记停机） |
| 模具工装 | 台账：类型（模具、工装夹具、检具）、模穴数、设计寿命（模次）、预警比例、适用产品（不选不限）。领用到已下达 / 生产中的工单（可指定安装设备），校验适用产品，达到设计寿命的不能领用；报工时选择领用到该工单的模具，按 ⌈(合格 + 报废) / 模穴数⌉ 累计模次，达到预警比例、设计寿命时提醒有 `mes:mold:edit` 权限的人员；归还、送修 / 修复、报废，全部动作记入模具履历。有使用记录的不能删除。权限 `mes:mold:list/add/edit/remove/issue`（领用归还） |
| 委外加工 | 委外采购订单按委外件的默认 BOM 生成委外用料，向加工商发料（出库类型 OUTSOURCE，计入委托加工物资）、退料（OUTSOURCE_RETURN）；委外件收货时按收货数量核销用料，成本核算把核销的子件成本计入委外件入库成本（借 存货 / 贷 委托加工物资） |
| 产能排程 | 工作中心设每资源每日工时、资源数、工作日，工厂日历按日期调整（放假为 0、加班），工作中心的设置优先于全厂。单个工单排程：从计划开工日（早于今天按今天）起按工序顺序逐日占用产能（无限产能）；「全部排程」按计划开工日依次排、共享产能（有限产能）。负荷分析把各工序剩余工时平均分摊到排程区间的工作日，与产能对比 |
| 改量、拆分、返工、报废入库 | 已下达工单可改量（不少于已完工 / 已报工数量，用料需求重算）；可从未开工数量中拆出新的草稿工单（来源 SPLIT）。返工工单的用料为产品本身，工序取默认 BOM，完工后重新入库。报工报废的产品可「报废入库」到不良品仓（不计完工数量，累计不超过报废数，按其他入库计价） |

## 质量管理

顶部导航「质量」，代码在 `modules/mes`（`Qms*` 实体、服务、控制器，`/qms/*` 接口；检验单接口仍为 `/mes/inspection`），前端 `views/qms`、`views/mes/inspection`、`components/qms`。

| 功能 | 说明 |
| --- | --- |
| 检验方案 | 按检验类型 + 物料（或物料分类）定义检验项目：定量（上下限、单位）或定性（标准说明），可标记关键项目；抽样方式：全检、固定数量（允收不良数 Ac）、AQL 抽样。新建检验单时先按物料、再按物料分类匹配启用的方案 |
| AQL 抽样 | 按 GB/T 2828.1 正常检验一次抽样（`quality/AqlSampling`）：批量 + 检验水平（S-1 ~ S-4、I ~ III）查样本量字码，再按 AQL（0.040 ~ 6.5）查样本量与 Ac / Re（含 ↑ ↓ 箭头），样本量大于批量时全检 |
| 质量检验 | 来料（IQC，填采购入库单号带出供应商，物料须在该入库单中、送检数量不超过入库数量）、过程（IPQC，工单产品或用料）、成品（FQC，工单产品）、首件（FAI，工单产品 + 工序）。有方案时逐项录入：定量项目录入各样本实测值，超出上下限计为不合格；定性项目录入不合格数；不合格合计 ≥ Re 或关键项目不合格判为不合格，页面实时显示判定结果；也可以不按方案手工填写抽检数、不良数和结论。草稿 → 确认，确认后不能修改删除。物料勾选「来料检验」时采购入库后冻结为待检（`wms_stock.frozen_qty`，「仓库管理 → 库存冻结」），来料检验确认合格 / 让步接收后放行，不合格保持冻结；供应商绩效显示来料批次合格率，评估时质量得分默认取合格率；D 级供应商下单时提示 |
| 首件检验 | 工艺路线的工序勾选「首件检验」（工单下达时带入），该工序首件检验确认且不是不合格之前，累计报工（合格 + 报废）只能 1 件 |
| 不合格品处理（MRB） | 检验确认为不合格时自动生成（来料、成品按送检批量，过程、首件按不良数），也可手工登记（生产发现、客户投诉等，返工需填写工单号）。评审选择处置方式和责任方：**退货**（来料保持冻结，通知采购办理采购退货）、**返工**（按工单产品生成草稿返工工单）、**报废**（来料放行冻结并生成报废出库单草稿，仓库确认后出库；序列号物料手工出库）、**让步接收**（来料放行冻结）、**挑选**（只记录）。发布流程 `qms_ncr` 后评审改为提交审批，通过后执行处置，拒绝 / 撤回退回待评审。检验不合格生成的处理单不能删除，误判时取消 |
| 纠正预防（8D） | 来源：不合格品、客户投诉、内部发现、审核；创建时生成 D1 ~ D8 步骤（组建团队、问题描述、临时措施、根本原因、永久措施、实施验证、预防再发、总结表彰），各步骤填写内容、负责人并标记完成；全部完成后提交效果验证，有效关闭、无效退回处理中。「纠正预防逾期提醒」定时任务通知负责人；处理单详情可直接「发起 8D」 |
| 供应商索赔 | 可关联不合格品处理单；确认后财务生成红字应付单（来源 `QUALITY_CLAIM`，冲减应付，生成凭证 借 应付账款 / 贷 营业外收入）；取消已确认的索赔时删除该应付单（已核销或已生成凭证的不能取消）。mes 发布 `SupplierClaimConfirmedEvent` / `SupplierClaimCancelledEvent`，由 `FinBillService` 监听处理 |
| 质量分析 | 已确认检验单的批次合格率（按检验类型、按月趋势，让步接收计为合格）、不良类型柏拉图（累计占比）、供应商来料质量排名（合格率低的在前） |
| SPC | 定量检验项目的控制图：每张检验单的实测值为一个子组，子组大小取众数；1 用单值-移动极差图，2 ~ 10 用均值-极差图（A2、D3、D4、d2 系数），大于 10 用均值-标准差图（c4 按 Γ 函数计算）；过程能力 Cp = (USL - LSL) / 6σ、Cpk = min(USL - μ, μ - LSL) / 3σ（只有一侧规格限时取该侧），标出超出控制限的子组 |

权限：`qms:plan:list/add/edit/remove`、`mes:qc:list/add/edit/remove`（质量检验）、`qms:ncr:list/add/edit`（评审、取消）`/remove`、`qms:capa:list/add/edit`（填写步骤、提交验证）`/verify/remove`、`qms:claim:list/add/confirm`（确认、取消）`/remove`、`qms:analysis:list`、`qms:spc:list`。首页待办：检验单待确认、不合格品待评审、纠正预防逾期。

| 成本核算 | 按物料的计价方法核算（物料上设置，默认月末一次加权平均，详见下方「存货计价方法」），必须逐月核算（首次核算、存货期初之后的第一期除外）。数量取仓库流水（按单据业务日期归属期间、不含调拨），采购金额取不含税金额；按「被领用物料 → 工单产品」的顺序计算，工单成本 = 期初在产品 + 领料 × 单价 + 工时 × 人工费率 + 工时 × 制造费用率，完工按完成比例结转；本期（及之前）关闭的工单，剩余在产品转出为生产损失。生成成本结转凭证：领料 借 生产成本 / 贷 原材料、库存商品；人工和制造费用 借 生产成本 / 贷 制造费用（生产岗位工资计提时已计入制造费用）；制造费用差异（期末制造费用余额 = 实际发生 - 已分配）转主营业务成本；关闭工单损失转主营业务成本；完工、销售成本；项目领料 借 合同履约成本、委外发料 借 委托加工物资、低值易耗品部门领用 借 领用单的费用科目，其余其他出入库（盘盈盘亏）计入待处理财产损溢。有出库但单价为 0 的物料会提示补录存货期初。凭证未审核时可重新核算 |
| 存货计价方法 | 物料的「计价方法」（`wms/model/CostMethod`，字典 `wms_cost_method`）：月末一次加权平均（WEIGHTED）、移动加权平均（MOVING）、先进先出（FIFO），修改后从下一次核算生效。移动加权平均、先进先出的物料在核算时按出入库发生顺序（业务日期、流水顺序）逐笔计价（`MovingValuation`、`FifoValuation`）：采购入库按不含税金额（委外件加上按数量分摊的核销子件成本）、完工入库按工单单位成本入账，其他入库、退料、销售退货按当时的成本（移动加权为当前平均单价，先进先出为最早批次的单价），采购退货按退货金额冲减（先进先出冲减最近的批次）；出库数量超过结存时按最近单价计价并记为欠数。逐笔计价得到期末结存后，本期出库总成本 = 期初 + 采购 + 生产 + 其他入库 − 期末结存，按数量分摊到生产领用、销售、其他出库（`fin_material_cost.unit_cost` 为本期出库的平均单价，工单材料、项目领料等按该单价计价），所以出库总成本和期末结存与逐笔计价一致，同一期间内各出库之间按平均分摊。先进先出的期末结存批次保存在 `fin_cost_layer`，作为下一期的期初批次（与上期期末不一致时，如刚改为先进先出，以上期期末为一个批次）；撤销核算时一并删除 |
| 标准成本 | 按版本维护（版本名称、生效期间）：采购件手工维护标准单价（新建时可复制已有版本，否则取最近一次成本核算的单价，没有时取参考成本价），自制件按默认 BOM（用量 × (1 + 损耗率)）× 子件标准成本 + 本级工序标准工时 × 工作中心人工 / 制造费用率逐级卷算（BOM 有循环时报错）。草稿可改单价、重新卷算，改单价后须重新卷算才能发布；同一生效期间只能有一个发布的版本，取消发布后可修改。权限 `fin:stdCost:list/edit` |
| 成本差异 | 「成本核算 → 成本差异」：期间 P 使用生效期间不晚于 P 的最近一个已发布版本，分析本期完工（最后一次完工入库在本期）或关闭的非返工工单，实际成本为截至本期各期工单成本合计，标准成本 = 完工数量 × 单位标准成本。差异拆分：材料价格差异 = 实际材料 − Σ 实际耗用 × 子件标准成本；材料用量差异 = Σ 实际耗用 × 子件标准成本 − 标准材料（含工单 BOM 与标准 BOM 的不同）；人工、制造费用按标准小时费率（单位标准人工 / 单位标准工时）拆为效率差异（(实际工时 − 标准工时) × 标准费率）和费率 / 耗费差异；工单明细按子件列出标准用量、实际用量、用量差异和价格差异 |
| 销售提成 | 「销售 → 销售提成」（代码在 fin，`FinCommissionService`）：销售订单有业务员（`scm_order.salesman_id`，新建时取客户的负责销售，没有时为制单人，可在订单详情中修改）。按期间统计各业务员的业绩：销售额 = 销售出库不含税金额（扣除退货），毛利 = 销售额 - 数量 × 当期成本单价（未核算时取参考成本价），回款 = 收款核销的销售出库 / 退货应收单。提成规则（`fin_commission_rule`）按依据（销售额 / 毛利 / 回款）、业务员（可空）、物料分类（可空，回款不分分类）、业绩门槛（阶梯）、比例设置；对每个业务员、依据、分类取最具体（指定业务员 > 指定分类 > 通用）且门槛最高的已达成规则，不同依据的提成相加，计算明细以 JSON 存在明细行。草稿可重新计算（保留手工调整）、调整，确认后生成的工资表按员工关联的登录账号计入「销售提成」（`hr_payroll_item.commission`，计入应发工资）。权限 `fin:commission:list/rule/edit` |
| 预算 | 年度 × 部门（或全公司）× 科目（可为上级科目，执行数按下级汇总）编制 12 个月预算；执行数取已记账凭证（不含结转损益），费用类取借 - 贷，收入类取贷 - 借 |

| 薪酬 | 薪资档案（基本工资、岗位工资、补贴、社保 / 公积金基数、公积金比例）。每次建立或调整都按生效日期记录薪资历史（`hr_salary_history`），未来生效的调整到期后才计入，工资表按月末生效的薪资计算。生成月度工资表：日薪 =（基本 + 岗位）/ 21.75；事假、缺勤全扣，病假扣 40%；迟到早退每次扣 50；加班工作日 1.5 倍、休息日 2 倍、节假日 3 倍；绩效奖金按考核等级系数；社保个人 10.5%、单位 26%；个税按月度累进税率（起征点 5000）。可调整其他加扣项后确认，确认生成计提凭证（借 费用科目按部门和岗位类别：生产 → 制造费用、销售 → 销售费用、其余 → 管理费用 / 贷 应付职工薪酬），发放生成付款凭证（借 应付职工薪酬 / 贷 银行存款、应交个人所得税、其他应付款） |
| 绩效 | 考核方案（指标 + 权重）→ 对部门（含下级）发起考核，评分人为部门负责人 → 员工自评 → 评分 → 归档。等级 S ≥ 90、A ≥ 80、B ≥ 70、C ≥ 60、D，对应奖金系数 1.5 / 1.2 / 1.0 / 0.8 / 0 |
| 员工自助 | 登录即可访问（`/hr/self`）：本人档案、打卡、考勤日历、假期余额、请假加班申请与撤销、培训、工资条、考核自评与评分 |
| 社保方案与个税 | 社保方案（城市、社保 / 公积金基数上下限、养老 / 医疗 / 失业 / 工伤各险种个人与单位比例），薪资档案选择方案后按方案计算（基数按上下限取值），未选择的按默认比例（个人 10.5%、单位 26%）。个税按累计预扣法：本年累计应纳税所得额 = 累计（应发 − 个人社保公积金 − 专项附加扣除 − 5000），本月个税 = 累计应纳税额 − 此前已预扣；专项附加扣除（子女教育、继续教育、住房贷款利息、住房租金、赡养老人、婴幼儿照护）按月份区间计入 |
| 劳动合同 | 固定期限 / 无固定期限 / 以完成一定工作任务为期限 / 实习 / 劳务；生效中 → 已到期（到期日后由定时任务更新）/ 已续签 / 已终止，员工离职时自动终止。定时任务「劳动合同到期提醒」每天提醒人事 30 天内到期的合同 |

工资计算用到的比例、税率表（月度表和累计预扣的年度表）在 `HrConstants`。员工档案、请假按部门 + 关联账号做数据权限。

权限：`hr:employee:list/add/edit/remove/change`（异动）、`hr:position:*`、`hr:recruit:list/add/edit/remove/approve/candidate/hire`、`hr:training:*`、`hr:attendance:list/edit`（补卡）`/config`（班次、日历）、`hr:leave:list/approve`、`hr:salary:list/edit`、`hr:payroll:list/add/edit/remove/confirm/pay`、`hr:perf:list/add/edit/remove/score`（代为评分）、`hr:contract:list/edit`、`hr:social:list/edit`、`hr:deduction:list/edit`。

## 项目管理

代码在 `modules/pm`，前端 `views/pm`、`components/pm`。

| 功能 | 说明 |
| --- | --- |
| 项目 | 编号、客户、项目经理、计划日期、合同金额、税率、成本预算；规划中 → 进行中 → 已暂停 / 已完成 / 已关闭。有待审批工时时不能完成或关闭，有未开票收款计划时不能完成 |
| 成员与资源 | 成员角色、投入比例、小时成本（默认取薪资档案折算：月人工成本 / 174，审批工时时按最新薪资重新折算；手工指定的不变）。离职成员的投入比例清零。资源分配页统计规划中、进行中项目的成员投入比例合计，超过 100% 为超负荷，并给出剩余任务工时 |
| 计划进度 | WBS 任务树，末级任务由负责人更新进度；上级任务的计划日期、工时、实际工时、进度自下而上汇总，项目进度 = 末级任务进度按计划工时加权。前置任务完成后才能开始；甘特图展示计划与进度 |
| 工时 | 成员按任务填报，由项目经理审批（有全部数据权限的管理员也可以），项目关闭后不能再审批；工时、费用列表按项目的数据权限过滤；审批通过的工时计入任务实际工时和人工成本（工时 × 小时成本） |

| 项目核算 | 收款计划 → 开票（关联里程碑的须里程碑已完成；为项目客户生成应收单，来源「项目开票」，在财务中生成凭证、收款核销）；收入按完工百分比法确认；挣值分析：PV、EV、AC、SPI、CPI、EAC；按月成本趋势 |
| 项目月结 | 「项目核算 → 项目月结」按期间为每个项目生成凭证：已审批工时的人工成本 借 合同履约成本 / 贷 员工岗位类别对应的薪酬费用科目（工资计提时已计入费用，这里转入项目）；已审批的手工费用 借 合同履约成本 / 贷 其他应付款；有合同金额的项目按完工进度确认收入（借 合同负债 / 贷 主营业务收入），并按累计实际成本结转（借 主营业务成本 / 贷 合同履约成本）。分录带项目辅助核算和项目部门（计入部门预算执行）。只处理未入账的部分，删除月结凭证后可重新月结；已入账的费用不能删除 |
| 订单与预算 | 销售订单、赢单商机可一键建项目（带入客户、金额，订单与项目一对一）；项目可开启超预算控制：费用、领料超过成本预算（有分类预算按分类）时不能录入 |
| 工时校验 | 填报工时与考勤核对：全天请假不能填报；超过当天出勤（含加班）时保存成功但给出提示 |

## 数据校验与主数据保护

- **删除主数据**：删除物料、仓库、客户、供应商、用户、部门前，各业务模块检查自己的单据是否引用（`framework/ref/ReferenceChecker`，每个模块一个 `XxxReferenceChecker` + `XxxRefMapper.xml`），被引用时只能停用。新增业务表引用主数据时，在对应模块的 `XxxRefMapper.xml` 中加一行。
- **停用**：停用的物料、仓库不能再入库，但剩余库存可以出库、调出、退货。
- **操作日志脱敏**：密码、薪资类金额完全隐藏，身份证号、银行卡号、手机号保留首 3 位和末 4 位（`OperLogAspect`）。
- **商务智能数据权限**：多维分析、自定义报表、仪表盘中的销售按制单部门或客户负责人、生产和财务按部门过滤；经营驾驶舱、决策分析汇总全公司数据，只对有「全部数据」权限的用户开放。
- **草稿订单删除**：发布 `OrderDeletedEvent`，商机解除对订单的引用，可重新生成订单。客户详情的订单数、最近下单只统计已审核及之后的订单。

## 数据访问规范

- **SQL 只写在 XML 里**：自定义 SQL 统一放在各模块的 `src/main/resources/mapper/<模块>/*.xml`，Java 代码里不写 SQL 字符串。单表的简单条件查询可以用 MyBatis-Plus 的 `Wrappers`。
- **复杂查询必须写 XML**：多表关联、分组统计、批量写入、清空表都写在 XML 里，并保证性能。
  - **统计放在数据库里做**：用 `GROUP BY` / `COUNT` 在数据库聚合，不把明细查到内存再算。示例：`DashboardMapper.xml` 的登录趋势、首页计数。
  - **批量写入用一条 SQL**：用一条 `INSERT ... VALUES (...), (...)`，不在循环里逐条插入。示例：`SysRoleMenuMapper.insertBatch`。
  - **关联查询一次查完**：用 JOIN 一次查出，避免 N+1 查询。示例：`SysRoleMapper.selectRoleNamesByUserId`。
  - **清空大表用 TRUNCATE**：不要逐行 DELETE。示例：`SysOperLogMapper.truncate`。
  - **不对索引列套函数**：WHERE 里对索引列只写范围条件，比如 `login_time >= ?`，不写成 `DATE(login_time) = ?`，否则索引会失效。
- **列表只查需要的列**：大字段（请求参数、返回结果等）和敏感字段（密码）不在列表里返回，详情接口再按主键查询。
- **索引**：WHERE、JOIN、ORDER BY 用到的列要有索引，关联表的反向查询也要建索引，比如 `sys_user_role.role_id`。统计类查询尽量做到只读索引就能出结果。
- **兜底防护**：分页单页最多 500 条（`MybatisPlusConfig.MAX_PAGE_SIZE`）；不带 WHERE 的 UPDATE、DELETE 会被拦截。
- **Redis 批量读写**：批量读取用 `CacheService.getAll`（Redis 实现是一次 `MGET`）；只需要数量时不读取值。

## 新增一个业务模块

以「订单」模块 `order` 为例：

1. **后端**：新建模块 `lemon-modules/lemon-order`。
   - `settings.gradle` 的模块清单里加 `'order'`；`lemon-order/build.gradle` 应用 `id 'lemon.java-conventions'`，依赖 `api project(':lemon-framework')`（需要其他业务模块时再加对应的 `project(...)`，不能形成循环）；`lemon-admin/build.gradle` 里加 `implementation project(':lemon-modules:lemon-order')`。
   - 代码放在 `src/main/java/com/lemon/erp/modules/order/{controller,service,mapper,entity,dto}`。实体继承 `common.base.BaseEntity`，Mapper 继承 `BaseMapper`，会被 `@MapperScan("com.lemon.erp.modules.*.mapper")` 自动扫描。
   - 自定义 SQL 写在本模块的 `src/main/resources/mapper/order/*.xml`。
   - 新增了缓存前缀时，在 `CacheMonitorService.CACHES` 里登记，才会出现在「缓存监控」中。
   - 接口加 `@PreAuthorize("@ss.hasPerm('order:xxx:list')")`，增删改接口加 `@OperLog`。
   - 新增接口用 `@Validated(Create.class)`，修改用 `@Validated(Update.class)`。
2. **前端**：新建 `lemon-web/src/api/order/*.js` 和 `lemon-web/src/views/order/xxx/index.vue`。
   - 列表页参照 `views/system/user/index.vue`：根元素加 `class="table-page"`，表格卡片加 `table-card`，表格 `:scroll="{ x: ..., y: '100%' }"`，即可获得固定表头、只有表格滚动的效果。
   - 状态、类型等用字典：`const dict = useDict('sys_common_status')` + `<DictTag>`。
   - 新增 / 编辑表单用 `useFormDrawer` + `<FormDrawer>`：自带加载详情、校验、保存、未保存修改的关闭确认、Ctrl/⌘ + Enter 保存。
   - **抽屉还是子页**：字段少的简单资料（仓库、库位、职位等）用抽屉；有明细行、字段多的单据表单加 `<FormDrawer page>`，详情页用 `<SubPage>`（用法同 `a-drawer`：`open` / `title` / `@close`，插槽 `extra`、`footer`）。子页占满内容区、覆盖在列表之上，返回后列表的筛选、分页、滚动位置不变；从详情点「编辑」时编辑子页叠在详情上，保存后回到详情并刷新（详情组件 `defineExpose({ reload })`）。
   - 需要按部门隔离的数据：表里加 `dept_id`、`create_by`，查询方法加 `@DataPermission`。
   - 新建的表加 `tenant_id`（见「SaaS 多租户」），新租户需要的基础数据实现 `TenantInitializer`。
3. **配置权限**：在「菜单管理」里新增目录、菜单（组件路径填 `order/xxx/index`）和按钮权限，再到「角色管理」里分配给角色。
